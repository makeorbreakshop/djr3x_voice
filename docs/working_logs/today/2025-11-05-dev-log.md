## [16:17] Issue #XX: Warp Terminal Mouse Click Detection Not Working

**Issue**: Mouse clicks not detected for microphone recording control when running DJ R3X in Warp terminal.

**Root Cause**: Warp terminal has known issues with macOS Accessibility permissions for global mouse event capture via pynput library, even when Accessibility permissions appear to be granted.

**Changes**:
- Created diagnostic test script `test_mouse_permissions.py` to verify pynput functionality
- Tested mouse click detection in both Warp and Terminal.app
- Confirmed issue is Warp-specific, not a code problem

**Solution**: Use Terminal.app instead of Warp for running DJ R3X until Warp fixes their Accessibility integration.

**Impact**: Mouse click recording control now works reliably in Terminal.app.

**Testing Method (Claude Code)**:
- Created and ran `test_mouse_permissions.py` using `./venv/bin/python`
- Verified pynput installation and listener creation successful
- Confirmed 0 clicks detected in 10 second window
- Isolated issue to terminal permissions, not code

**Learning**: Some modern terminals (like Warp) don't properly support system-level event capture even with Accessibility permissions enabled.

## [16:28] Bug #XX: Music Playback Completely Broken - VLC Returns None

**Issue**: Music playback not working at all. VLC warnings during startup:
```
WARNING - Could not get duration for *.mp3: 'NoneType' object has no attribute 'media_new'
```

**Root Cause**: Setting `VLC_PLUGIN_PATH` environment variable to empty string (`''`) in `music_controller_service.py:22` causes VLC to fail initialization and silently return `None` instead of a valid Instance object.

**Changes**:
- Removed `os.environ['VLC_PLUGIN_PATH'] = ''` line from `music_controller_service.py`
- Kept `VLC_VERBOSE = '-1'` to suppress excessive logging
- Added comment explaining why VLC_PLUGIN_PATH should not be set

**Impact**: Music playback now works correctly, VLC initializes properly with all tracks loading with durations.

**Testing Method (Claude Code)**:
- Used Bash tool to run DJ R3X in the correct virtual environment: `cd cantina_os && ../venv/bin/python -m cantina_os.main`
- Piped commands to test services: `echo -e "list music\nquit" | ../venv/bin/python -m cantina_os.main`
- Created isolated Python test scripts to reproduce VLC initialization issue
- Tested VLC Instance creation with/without `VLC_PLUGIN_PATH` environment variable
- Monitored startup logs to see VLC warnings disappear after fix
- Verified music tracks load with proper durations (no more 'NoneType' errors)
- **Key**: Always used `../venv/bin/python` to ensure correct dependencies, not system Python

**Learning**: Setting VLC_PLUGIN_PATH to empty string prevents VLC from finding its plugins, causing silent initialization failure. Leave environment variables unset if you don't need to override them.
