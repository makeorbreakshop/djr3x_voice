### The Real Problem: Multi-Person Attribution

The system only tracks **one person at a time** (`_current_person`), creating two issues:

**Issue 1: Person Exits Before Mode Change**
- Camera loses sight of person during conversation
- `_current_person` set to `None`
- System forgets WHO to summarize for
- **Solution**: Track `_last_person_with_conversation` separately

**Issue 2: Multi-Speaker Conversations** (More Complex)
```
Brandon: "This is Millie, my daughter"
  → _current_person = "Brandon"
  → Logged to Brandon's profile ✓

Millie: "My favorite color is blue"
  → Still _current_person = "Brandon" (camera sees Brandon)
  → WRONG: Logged to Brandon's profile ✗
  → Millie's profile never created ✗
  → Preference never saved ✗
```

**The system has no way to know WHO is speaking!**

---

### Solution Options

#### Option 1: Fix Immediate Bug (Quick Win)

Add `_last_person_with_conversation` tracking to `MemoryService`:

```python
class MemoryService:
    def __init__(self):
        self._current_person: Optional[str] = None
        self._last_person_with_conversation: Optional[str] = None  # NEW
        self._person_needs_summary: bool = False

    async def _handle_person_exited(self, payload):
        # When person exits, preserve who they were for later summarization
        if self._current_person:
            self._last_person_with_conversation = self._current_person
        self._current_person = None

    async def _handle_system_mode_change(self, payload):
        old_mode = payload.get("old_mode")

        # Use last person if current person is None
        person_to_summarize = self._current_person or self._last_person_with_conversation

        if old_mode == "INTERACTIVE" and person_to_summarize and self._person_needs_summary:
            await self._update_person_summary(person_to_summarize)
            self._person_needs_summary = False
            self._last_person_with_conversation = None  # Clear after use
```

**Benefits**:
- ✅ Fixes camera-exit-before-mode-change bug
- ✅ Preserves conversation summaries
- ✅ Simple, low-risk change

**Limitations**:
- ❌ Doesn't solve multi-speaker attribution
- ❌ Still logs everything to one person

#### Option 2: Add Memory Update Tools (Medium Complexity)

Register tools with ClaudeService for explicit memory management:

**New Tools**:
```python
# Tool 1: Create/update person profile
{
  "name": "remember_person_info",
  "description": "Save information about a person you meet",
  "parameters": {
    "person_name": "Millie",
    "relationship": "daughter of Brandon",
    "preferences": {"favorite_color": "blue"},
    "notes": "Child, likes pop music"
  }
}

# Tool 2: Attribute current statement to specific person
{
  "name": "set_current_speaker",
  "description": "Indicate who is currently speaking when multiple people present",
  "parameters": {
    "speaker_name": "Millie"
  }
}
```

**Flow**:
```
Brandon: "This is Millie, my daughter"
  → Claude calls: remember_person_info("Millie", relationship="daughter")
  → Profile created

Brandon: "Millie is going to talk next"
  → Claude calls: set_current_speaker("Millie")
  → Next transcriptions attributed to Millie

Millie: "My favorite color is blue"
  → Logged to Millie's profile ✓
  → Claude calls: remember_person_info("Millie", preferences={"favorite_color": "blue"})
  → Preference saved ✓
```

**Benefits**:
- ✅ Explicit control over memory updates
- ✅ Can handle multi-person conversations
- ✅ Claude can infer speaker from context
- ✅ Works with current architecture

**Limitations**:
- ⚠️ Relies on Claude correctly identifying speakers
- ⚠️ May miss rapid speaker changes
- ⚠️ Requires good persona instructions
