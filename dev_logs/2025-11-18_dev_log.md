```python
async def _handle_person_detected(self, payload: Dict[str, Any]) -> None:
    """Handle VISION_PERSON_DETECTED event."""
    person_name = payload.get("person_name", "Unknown")
    confidence = payload.get("confidence", 0.0)
    timestamp = payload.get("timestamp", time.time())

    # Store current person and update person_memory
    await self.set("current_person_present", person_name)
    await self.set("last_person_detection_time", timestamp)

    person_memory = self._state.get("person_memory", {})
    if person_name not in person_memory:
        person_memory[person_name] = {}
    person_memory[person_name]["last_seen"] = timestamp
    person_memory[person_name]["confidence"] = confidence
    await self.set("person_memory", person_memory)

async def _handle_person_exited(self, payload: Dict[str, Any]) -> None:
    """Handle VISION_PERSON_EXITED event."""
    await self.set("current_person_present", None)
    await self.set("last_person_exit_time", timestamp)
```

## Session 3: Continuous Face Recognition Integration

### Overview
Integrated continuous face recognition monitoring into VisionService. Restored features that were lost during merge conflict in Session 2. System now performs real-time person detection and emits events when people enter/exit the camera view.

### Changes Made

**Added configuration parameters to `__init__`:**

**Added person tracking state variables:**
- `_current_person`: Currently detected person name
- `_current_person_confidence`: Current detection confidence
- `_person_detection_time`: When person was first detected
- `_no_person_frames`: Counter for person absence (hysteresis)
- `_person_exit_threshold`: Frames before emitting PERSON_EXITED (default: 10 frames = 2 seconds)

**Added monitoring task management:**
- `_monitoring_task`: AsyncIO task for continuous loop
- `_monitoring_running`: Flag to control loop execution

#### 2. Face Encoding Loading
**Method**: `_load_face_encodings()`

Loads trained face encodings from `vision_data/face_encodings.pkl`:
- Checks if `face_recognition` library is available
- Loads pickled dictionary of {name: encoding} mappings
- Logs number of people loaded
- Gracefully handles missing file or errors

**Startup behavior:**
- If no encodings found: Logs warning, monitoring disabled
- If encodings loaded: Monitoring starts automatically

#### 3. Continuous Monitoring Loop
**Method**: `_continuous_monitoring_loop()` (async)

Background task that runs at configured FPS:
1. Opens camera for continuous capture
2. Captures frames in loop
3. Runs face recognition on each frame (in thread to avoid blocking)
4. Calls `_handle_person_detection()` with results
5. Sleeps to maintain target FPS
6. Releases camera on stop

**Error handling:**
- Retries on frame capture failures
- Logs errors without crashing
- Graceful shutdown on cancellation

**Lifecycle:**
- Started in `_start()` if enabled + face_recognition available + encodings loaded
- Stopped in `_stop()` with proper task cancellation

#### 4. Face Recognition
**Method**: `_recognize_face(frame)` (sync, called in thread)

Uses `face_recognition` library to identify people:
1. Converts BGR (OpenCV) → RGB (face_recognition)
2. Detects face locations using HOG model (faster than CNN)
3. Computes face encodings for detected faces
4. Compares against all known face encodings using face distance metric
5. Returns best match if distance < threshold

**Returns**: `(person_name, confidence)` or `(None, 0.0)` if no face

**Performance:**
- Uses HOG model for speed (~5 FPS sustainable)
- Runs in thread via `asyncio.to_thread()` to avoid blocking event loop
- Processes only first detected face (assumes single person)

#### 5. Person Detection State Machine
**Method**: `_handle_person_detection(person_name, confidence)` (async)

Implements state machine with hysteresis to prevent event flickering:

**State transitions:**
- **No person → Person detected**: Emits `VISION_PERSON_DETECTED`
- **Person A → Person B**: Emits `PERSON_EXITED` for A, then `PERSON_DETECTED` for B
- **Person → No person (temporary)**: Waits N frames before emitting exit
- **Person → No person (sustained)**: Emits `VISION_PERSON_EXITED` after threshold

**Events emitted:**
```python
VISION_PERSON_DETECTED: {
    "name": "Brandon",
    "confidence": 0.85,
    "timestamp": 1234567890.0
}

VISION_PERSON_EXITED: {
    "name": "Brandon",
    "duration_seconds": 45.2,
    "timestamp": 1234567935.2
}
```

**Hysteresis logic:**
- Person must be absent for 10 consecutive frames (2 seconds at 5 FPS) before exit event
- Prevents flickering from temporary occlusions or detection failures
- Tracks `_no_person_frames` counter, resets on detection

### Technical Details

### Changes Made

#### Face Encoding Format Compatibility
**File**: `cantina_os/cantina_os/services/vision_service.py`

```python
    'names': ['Brandon', 'Brandon', ...]
}
```

**New format** (expected by VisionService):
```python

}
```

**Implementation:**
- Detects format by checking for 'encodings' and 'names' keys
- Converts legacy format on-the-fly during load
- Handles duplicate names (takes first encoding)
- Logs format conversion for debugging
- Falls back gracefully for unknown formats

**Code changes:**
```python
# Check if it's the legacy format
if isinstance(data, dict) and 'encodings' in data and 'names' in data:
    # Convert to new format: {name: encoding}
    self.known_face_encodings = {}
    for name, encoding in zip(names_list, encodings_list):
        if name not in self.known_face_encodings:
            self.known_face_encodings[name] = encoding
elif isinstance(data, dict):
    # New format - use directly
    self.known_face_encodings = data
```

**Result**: Camera resource conflict, startup scene capture fails

### Proposed Architecture: Unified Vision Processing

#### Core Problem
Current implementation has camera usage split across two independent systems:
- **Startup scene capture**: Separate method, one-time use, calls Claude vision API
- **Continuous monitoring**: Separate loop, ongoing face recognition, no Claude calls

This violates the principle of single camera ownership and causes resource conflicts.

#### Solution: Single Monitoring Loop with Smart Scene Updates

**Unified Approach:**
- ONE monitoring loop owns the camera
- EVERY frame: Run face recognition (cheap, local, ~5 FPS)
- SELECTIVE frames: Send to Claude vision API (expensive, smart)

**When to Call Claude Vision API:**

1. **First Frame (Startup)**
   - System boots → monitoring starts
   - Frame 1: Run face recognition + send to Claude
   - Enriched prompt: "Describe scene. Face recognition detected Brandon (confidence 0.85)"
   - Emit: VISION_PERSON_DETECTED + VISION_SCENE_CAPTURED
   - Result: ClaudeService has full context immediately

2. **Person Changes**
   - Brandon leaves → emit VISION_PERSON_EXITED (after 2-sec hysteresis)
   - Sarah enters → face recognition detects change
   - Capture NEW scene with Sarah's context
   - Emit: VISION_PERSON_DETECTED + fresh VISION_SCENE_CAPTURED
   - Result: ClaudeService context stays current

3. **Scene Staleness**
   - If scene >5 minutes old and person still present
   - Auto-refresh scene to keep context current
   - Prevents stale environmental descriptions

4. **On-Demand Request**
   - User asks "what do you see?"
   - VISION_ON_DEMAND_REQUEST event triggers fresh capture
   - Always provides up-to-date answer

**What Runs Continuously:**
- Face recognition every frame (~200ms intervals)
- Person presence tracking
- State machine for person enter/exit detection
- Event emission for person state changes
- NO Claude API calls (unless conditions above met)

#### Benefits

**Architecture:**
- ✅ Single camera ownership (no resource conflicts)
- ✅ Unified processing pipeline
- ✅ Clear separation: local (face recognition) vs. cloud (Claude vision)

**Context Awareness:**
- ✅ Scene descriptions include person identification
- ✅ Context stays fresh as people enter/exit
- ✅ Rich prompts: "Brandon detected" enriches scene description

**Cost Efficiency:**
- ✅ Minimal API calls (only when meaningful changes occur)
- ✅ Face recognition runs locally (fast, free)
- ✅ Smart update logic prevents unnecessary captures

**User Experience:**
- ✅ ClaudeService always has current person + scene context
- ✅ "What do you see?" always accurate
- ✅ Natural conversation flow (knows who's there and what changed)

**Event Flow After Refactor:**

```
VisionService._continuous_monitoring_loop()
  ├─ Frame N captured
  ├─ Face recognition → person_name, confidence
  ├─ _handle_person_detection(person_name, confidence)
  │   ├─ Person state changed?
  │   │   ├─ YES → Emit VISION_PERSON_DETECTED/EXITED
  │   │   └─ Should update scene?
  │   │       ├─ First frame? YES → capture
  │   │       ├─ Person changed? YES → capture
  │   │       ├─ Scene stale (>5 min)? YES → capture
  │   │       └─ NO → skip capture
  │   └─ If capturing → _capture_scene_with_person()
  │       ├─ Build prompt: "Face recognition detected {name}..."
  │       ├─ Call Claude vision API
  │       └─ Emit VISION_SCENE_CAPTURED
  └─ ClaudeService receives events:
      ├─ Stores current_person (from PERSON_DETECTED)
      └─ Stores current_scene (from SCENE_CAPTURED)
```

After refactor:
